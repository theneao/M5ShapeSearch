### 2.2 新增扩展组件（3个，不修改核心LVGL库）

#### 🧩 lv_draw_canvas - 手绘画布组件

- **继承**：扩展 `lv_canvas`
- **核心能力**：
  - 多点触控采样（60Hz）+ 环形缓冲区（2048点）
  - 实时绘制：**双缓冲策略**（前台画点 + 后台累计曲线），避免频繁重绘卡顿
  - 内置 **Douglas-Peucker (DP) 算法** 特征点压缩（目标压缩比 ≥ 85%）
  - 触控压力可选（线条粗细变化）
  - 清理/撤销/品类切换回调接口
- **内存占用**：画布缓冲 466×380×2 ≈ 345KB（PSRAM 分配）

#### 🧩 lv_kline_chart - K线图组件

- **继承**：基于 `lv_obj` 自定义绘制（不继承 `lv_chart`，性能不足）
- **核心能力**：
  - 分层渲染：蜡烛层 → MA均线层 → 成交量层 → 十字光标层
  - **仅绘制视野内可见K线**（脏矩形局部刷新）
  - 手势识别：单指平移（含 `easeOutCubic` 惯性衰减）、双指捏合缩放（1x~10x，以触点为中心）
  - 数据接口：`set_visible_range(start_idx, end_idx)` 配合外部三级缓存
  - MA均线**离屏预渲染**到 Sprite，缩放时直接缩放 Sprite 减少计算
- **目标帧率**：滑动/缩放 ≥ 59fps

#### 🧩 lv_chip_group - 多选筹码组件

- **继承**：基于 `lv_obj` 容器 + 内部动态 `lv_btn`
- **核心能力**：
  - 单选模式（指标大类）/ 多选模式（具体条件）
  - 非线性滑动选中动画（0.2s easeOutExpo）
  - 自动换行 / 横向滚动两种布局
  - 选中回调 `on_selection_changed(std::vector<item_id>)`
- **触控热区**：每个 Chip 最小 48×32 dp（符合嵌入式误触标准）

```cmake
# main/CMakeLists.txt 修改前
file(GLOB_RECURSE MY_SRCS "apps/*.c" "apps/*.cpp" ...)

# 修改后（排除列表）
set(EXCLUDE_APP_PATTERNS
    "apps/app_alarm_clock/*"
    "apps/app_badge/*"
    "apps/app_fft/*"
    "apps/app_imu/*"
    "apps/app_lucky_wheel/*"

    "apps/app_template/*"
    "assets/images/watch_face/classic/*"
    "assets/images/watch_face/number_flow/*"
    "assets/images/watch_face/simple/*"
)
file(GLOB_RECURSE MY_SRCS "apps/*.c" "apps/*.cpp" "assets/*.c" "hal/*.cpp")
# 遍历过滤
foreach(SRC ${MY_SRCS})
    foreach(PAT ${EXCLUDE_APP_PATTERNS})
        if(SRC MATCHES "${PAT}")
            list(REMOVE_ITEM MY_SRCS "${SRC}")
        endif()
    endforeach()
endforeach()
```

### 5.2 Docker 三容器编排（一键启动）

服务器部署命令：
```bash
$ git clone https://your-repo/stock-match-server.git
$ cd stock-match-server
# 填写配置：.env (TUSHARE_TOKEN、DOMAIN)
$ docker compose up -d
# ✅ 启动完成：自动申请HTTPS证书 + 预计算FAISS索引（首次≈10分钟）+ API就绪
```

**`docker-compose.yml` 核心模板：**

```yaml
version: "3.8"
services:
  nginx-proxy:
    image: nginx:1.27-alpine
    ports: ["80:80", "443:443"]
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./certbot/conf:/etc/letsencrypt:ro
    depends_on: [match_server]
    restart: unless-stopped
    networks: [backend]

  match_server:
    build: ./server
    expose: ["8000"]
    environment:
      - TUSHARE_TOKEN=${TUSHARE_TOKEN}
      - REDIS_URL=redis://cache:6379
      - FAISS_INDEX_DIR=/data/faiss_indexes
    volumes:
      - ./data/faiss_indexes:/data/faiss_indexes
    depends_on: [cache]
    deploy: { replicas: 1, resources: { limits: { memory: 4G } } }
    restart: unless-stopped
    networks: [backend]

  cache:
    image: redis:7.2-alpine
    command: ["redis-server", "--maxmemory", "2gb", "--maxmemory-policy", "allkeys-lru"]
    volumes: [./data/redis:/data]
    restart: unless-stopped
    networks: [backend]

  cron_job:
    build: ./cron
    environment:
      - TUSHARE_TOKEN=${TUSHARE_TOKEN}
      - REDIS_URL=redis://cache:6379
      - ENABLE_CRYPTO=1
      - ENABLE_STOCK=0         # Phase1 关股票，节省预计算时间
      - ENABLE_FUTURES=0
    volumes:
      - ./data/faiss_indexes:/data/faiss_indexes
    depends_on: [cache]
    restart: unless-stopped
    networks: [backend]

networks:
  backend:
    driver: bridge
```

### 5.3 形态匹配 5 分钟预计算流水线

```
  Cron 定时器（每5分钟触发）
        │
        ▼
  ┌────────────────────────────────────────────┐
  │ Step 1：增量拉取K线（仅拉最新 2~5 根）       │
  │  · 仅最新K线更新，历史K线995根直接读Redis缓存 │
  │  · 8250标的 × 3TF → 流量 ≈ 14.85MB/次      │
  └────────────────────┬───────────────────────┘
                       ▼
  ┌────────────────────────────────────────────┐
  │ Step 2：形态窗口滑切（重叠率50%）           │
  │  · 窗口大小：60~180根K线（3种长度）         │
  │  · 每标的生成 ≈ 2000 个形态样本             │
  └────────────────────┬───────────────────────┘
                       ▼
  ┌────────────────────────────────────────────┐
  │ Step 3：形态特征提取（与设备端代码 100% 一致）│
  │  · 128点 等距重采样 + min-max 归一化        │
  │  · 16维统计特征增强（波动率/偏度/回撤等）   │
  │  · 拼接为 164维 float16 向量                │
  └────────────────────┬───────────────────────┘
                       ▼
  ┌────────────────────────────────────────────┐
  │ Step 4：写入 FAISS 索引（分 6 个独立桶）    │
  │  · 按 category × timeframe 分桶查询         │
  │  · 桶：crypto_1d / crypto_1h / stock_1d /  │
  │         stock_1h / futures_1d / futures_1h │
  │  · 同时写元数据库 SQLite：faiss_id → 标的信息│
  └────────────────────────────────────────────┘
```

|---|---|---|
| 单次耗时 | ≈ 7分40秒 | ≈ 48秒 |
| 月流量（入网免费） | ≈ 31GB | ≈ 2.5GB |
| 内存峰值占用 | ≈ 4.2GB | ≈ 280MB |

### 5.4 指标预计算引擎（与形态流水线并行执行）

```
  同一 Cron 5分钟触发，独立线程并行
        │
        ▼
```

### 8.3 验收工具与方法

1. **设备端时延**：在关键回调处打 `esp_timer_get_time()` 微秒级日志
2. **设备端帧率**：开启 `LV_USE_PERF_MONITOR 1`，叠加显示 FPS/CPU
3. **设备端内存**：每 500ms 采样 `heap_caps_get_free_size(MALLOC_CAP_8BIT)` 记录最小值
4. **固件体积**：`idf.py size` 查看 Flash 各段占用
5. **服务端性能**：FastAPI 内置 middleware 打点 + Prometheus + Grafana 面板
6. **回归测试**：连续执行 100 轮 [手绘→筛选→详情→缩放→返回] 全链路，内存泄漏 ≤4KB/轮

## 十、关键技术风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| **手绘匹配时延 >1.5s** | 核心体验不达标 | 1) 设备端预提取features_16d省云端重算 2) HTTP KeepAlive预热连接 3) Redis热点结果缓存 4) 180ms超时降级返回缓存 |
| **K线缩放 <55fps** | 丝滑感缺失 | 1) 仅绘制视野内可见K线 2) MA离屏Sprite预渲染+缩放 3) 异步解码 4) 开启M5GFX DMA2D |
| **内存超80%阈值** | 系统崩溃 | 1) LVGL大缓冲PSRAM分配 2) K线float16紧凑结构体 3) 进入详情释放手绘画布 4) heap_caps定期检查 |
| **服务器月成本超支** | 运营费用高 | 1) Phase1仅启用Crypto（2C2G ¥30/月），验证OK再扩全品类(4C8G ¥80/月) 2) 入网流量免费100%利用 |
| **FAISS索引构建失败** | 形态匹配不可用 | 1) SQLite保存faiss_id映射，索引损坏可重放重建 2) 每次全量构建前做快照备份 3) 监控告警 |
| **Redis倒排集合写一半读** | 筛选结果脏数据 | 1) tmp前缀临时集合写入 → RENAME原子替换（零中断） 2) 写入时加分布式锁（可选） |
| **网络断开/WiFi切换** | 功能瘫痪 | 1) Config AP 一键重配 2) 结果列表缓存上次查询（5分钟TTL） 3) 友好无网降级UI+重连倒计时 |
| **触控采样不均** | 手绘抖/断 | 1) 3次滑动平均滤波 2) 中断级时间戳对齐 3) Bezier二次曲线插值平滑 |
| **预计算流水线超时>8分钟** | 服务端指标不更新 | 1) 分布式多Worker并行（8进程/品类独立） 2) 超时自动重启 3) 指标过期>10分钟API返回告警提示 |
